COMPLIANCE TRACKER — HOW IT WORKS (SIMPLE VERSION)
=====================================================

Think of it as one client's data travelling through 7 stages, from
"who is this client" to "is anything overdue right now."


1. CLIENT DETAILS COME IN
   Basic facts about the client — PAN, GST number, company type, turnover,
   income, how many directors, etc. This comes from KDK.

2. THE SYSTEM WORKS OUT WHICH FILINGS APPLY
   Not every client has to file every form. The system looks at the
   client's details and checks them against the full list of statutory
   filings (GST, TDS, Income Tax, ROC, PF/ESI...) to decide which ones
   actually apply to THIS client — and can show why.

3. DUE DATES GET CREATED
   For every filing that applies, the system works out the actual
   deadline for each period — e.g. "GST return for July, due 20th August."

4. EACH CLIENT + EACH DEADLINE = ONE TRACKED ITEM
   This is the real unit the whole app is built on: one client, one
   filing, one due date. It carries a status (Filed / Pending / Overdue),
   how many days late it is, and the estimated penalty if it stays late.

5. REMINDERS GO OUT ON THEIR OWN
   A set schedule — a week before, 3 days before, on the day, and after —
   automatically sends a WhatsApp or email reminder, without staff having
   to remember to chase anyone.

6. FILING GETS MARKED DONE
   Once it's filed — confirmed on the government portal, synced
   automatically from KDK, or marked by hand — the item closes and the
   reminders stop. It always records who marked it and when.

7. EVERYTHING ADDS UP INTO ONE SCREEN
   All these tracked items roll up into simple views: what's overdue
   today, what's due this week, which clients need attention — instead
   of showing a giant list of every single item for every client.


IN ONE LINE
------------
Client details come in -> system figures out what they must file ->
deadlines get created -> reminders go out automatically -> filing gets
confirmed -> the dashboard shows what still needs attention.
